## 正文

很多人第一次接触 AI Agent，会把它理解成：

> “用户提问 → 大模型回答”

但一个真正能执行任务的 Agent，通常还要处理工具调用、上下文记忆、定时任务、浏览器和终端环境。下面用一张窄屏友好的 ASCII 图，拆开 Hermes Agent 的主要结构。

```text
                 +----------------+
                 | USER / DEVELOPER|
                 +-------+--------+
                         |
       +-----------------+-----------------+
       |                 |                 |
   +---v---+         +---v---+         +---v---+
   | CLI   |         |DESKTOP|         |GATEWAY|
   | TUI   |         |Electron|        |TG/Slack|
   +---+---+         +---+---+         +---+---+
       \                 |                 /
        +----------------v----------------+
        |          AGENT CORE            |
        | context -> model -> tool calls |
        +----------------+---------------+
                         |
       +-----------------+-----------------+
       |                 |                 |
   +---v---+         +---v---+         +---v---+
   | MODEL |         | TOOLS |         |POLICY |
   |provider|          |browser|         |config |
   |streaming          |terminal         |profiles|
   +---+---+         +---+---+         +---+---+
       \                 |                 /
        +----------------v----------------+
        | MEMORY | SKILLS | CRON | SANDBOX|
        +---------------------------------+
```

### 这张图怎么读？

**第一层：入口。**  
Hermes 不只有命令行。用户可以从 CLI/TUI、Electron Desktop，或者 Telegram、Slack 等消息平台进入。

**第二层：Agent Core。**  
这是所有入口共享的“中枢”。它负责组织上下文、请求模型、解析模型返回的工具调用，并把结果继续送回对话。

**第三层：模型与工具。**  
模型负责推理，工具负责行动。浏览器、终端、文件、搜索等能力，让 Agent 不止“会聊天”，还可以真正完成任务。

**第四层：记忆与扩展。**  
SessionDB / FTS5 保存会话和检索信息；Skills、Plugins、MCP 提供可插拔能力；cron 和 subagents 负责自动化与并行工作。

**最底层：运行环境。**  
任务可以落在本地、Docker、SSH、Modal、Daytona 等环境中。也就是说，Agent 的“思考”和“执行”可以被拆开。

### Hermes 的一个关键设计

Hermes 把核心做成“窄腰”：

- 核心 Agent Loop 保持稳定；
- 新能力优先放到 skill、plugin、MCP 或服务侧；
- 同一个 Agent Core 可以复用于 CLI、桌面端和消息网关；
- 会话级 prompt cache 尽量保持稳定，避免每轮都重建上下文。

这是一种很实用的工程取舍：**核心越小，越容易维护；边缘越开放，越容易扩展。**

如果把它类比成一座城市：

- 入口层 = 不同的车站和道路；
- Agent Core = 城市交通中枢；
- Tools = 工厂、商店和公共设施；
- Memory = 城市档案馆；
- Plugins / Skills = 可以持续接入的新街区；
- Runtime Backend = 真正承载工作的园区。

所以，AI Agent 的重点并不只是“选择哪个模型”，而是如何把模型、工具、记忆和执行环境组织成一个可靠的闭环。

> 注：这是一张逻辑架构图，展示主要控制流，不等同于完整的部署拓扑或类图。
